- 문서 상태: Preproduction Lock v1.0
- 연결 작업: `TASK-20260830-02`
- 조사 기준일: 2026-08-30 (KST)
- 적용 범위: M1 2분 코어 증명부터 M3 MVP 후보까지
- 전제: 논리 해상도 960×540, 단일 Canvas 2D, 데스크톱 웹, 키보드+마우스 우선

## 1. 아트 디렉션 한 줄

**먹빛 폐도시를 얇고 절제된 벡터 면으로 눌러 두고, 플레이어가 만든 네온 연결망만 살아 움직이게 한다.**

목표는 일반적인 “네온 사이버펑크” 장식이 아니라 경로, 연결, 교란, 귀환 판단이 한 프레임에서 읽히는 기능적 레트로 퓨처 그래픽이다. 빛은 장식이 아니라 상태 정보다. 발광 면적을 화면의 약 15% 이내로 유지하고, 가장 밝은 값은 플레이 목표와 위험 예고에만 쓴다.

### 시각 기둥

1. **연결망이 주인공이다.** 지형보다 링크가 먼저 읽히며, 런 종료 화면도 플레이어가 만든 망의 형태를 중심에 둔다.
2. **실루엣이 색보다 먼저 말한다.** 모든 플레이 요소는 흑백·저채도 화면에서도 형태와 선 패턴으로 구분된다.
3. **정밀한 시스템과 거친 폐허가 대비된다.** 네트워크·UI는 정렬된 직선과 동심원, 도시는 끊기고 어긋난 큰 면으로 구성한다.
4. **효과는 짧고 원인에 붙는다.** 화면 전체 글로우, 상시 노이즈, 과한 색수차 대신 상호작용 지점에 짧은 펄스와 잔상을 사용한다.

## 2. 형태 언어

### 공통 문법

- 기본 각도는 수평·수직과 45°다. 곡선은 신호 파동, 보호 반경, 상호작용 진행에만 사용한다.
- 아군과 구축물은 **열린 형태와 바깥으로 뻗는 선**, 적은 **닫힌 덩어리와 안쪽을 향한 꼭짓점**을 쓴다.
- 중요한 상호작용은 `외곽 실루엣 + 내부 코어 + 상태 링`의 세 층으로 만든다.
- 외곽선은 기본 2px, 선택·위험 예고는 4px, 링크의 넓은 안전 영역은 저알파 8px 아래에 2px 코어를 겹친다.
- 장식용 1px 선은 월드 오브젝트에 쓰지 않는다. 960×540에서 축소 시 사라질 수 있기 때문이다.

### 플레이 요소 실루엣

| 대상 | 실루엣·내부 표식 | 움직임 문법 | 한눈에 읽혀야 할 정보 |
|---|---|---|---|
| 전달자 | 진행 방향을 가리키는 주황색 연꼴, 뒤쪽이 열린 V자 꼬리 | 이동 시 꼬리가 2단으로 벌어지고 대시 때 짧은 평행 잔상 | 위치, 조준 방향, 대시 가능 여부 |
| 본부 | 모서리가 잘린 큰 정사각형 안의 삼중 동심원 | 추출 중 링이 안쪽에서 바깥쪽으로 채워짐 | 귀환 지점, 추출 진행, 방어막 |
| 중계기 소켓 | 비어 있는 육각 링과 바닥의 3개 접점 | 설치 가능 시 접점이 순차 점등 | 설치 가능·불가 |
| 활성 중계기 | 열린 육각 프레임과 위쪽 안테나 두 갈래 | 네트워크 심박에 맞춰 코어가 천천히 호흡 | 온라인, 내구도, 하위 연결 |
| 데이터 패킷 | 흰색 마름모 2개가 어긋난 봉투형 코어 | 부유는 2px 이내, 회수 가능 시 한 번만 확장 펄스 | 회수 대상, 운반·업로드 상태 |
| 추격자 | 전방 꼭짓점이 긴 삼각 쐐기 | 돌진 전에 뒤로 4px 압축 | 근접 압박과 돌진 방향 |
| 사수 | 정사각 브래킷과 중앙 조준점 | 발사 전 브래킷이 목표 방향으로 정렬 | 사선과 발사 시점 |
| 교란자 | 안쪽이 파인 마름모와 끊긴 원 | 충전 중 끊긴 조각이 링크 방향으로 회전 | 링크 교란 범위와 남은 시간 |
| 파괴자 | 넓은 팔각형과 전면의 이중 해머 표식 | 중계기 공격 전 상체가 두 박자로 수축 | 중계기 우선 표적, 강한 단발 |
| 엘리트 | 원래 실루엣을 유지한 이중 외곽선과 작은 왕관형 노치 | 결합한 두 역할의 예고 동작을 그대로 사용 | 새 규칙이 아닌 역할 조합 |

색을 제거해도 `삼각=추격`, `브래킷=사격`, `파인 마름모=교란`, `팔각=파괴`가 남아야 한다. 방향별 걷기 스프라이트를 늘리기보다 실루엣 회전과 2~3프레임 추진 애니메이션으로 M1 범위를 제한한다.

### 적용 규칙

- 한 색은 한 기능을 가진다. 청록 장식 간판, 주황 적 탄환, 자홍 메뉴 강조는 만들지 않는다.
- 발광은 원색 코어 100% + 같은 색의 15~25% 알파 외곽 한 겹으로 제한한다. 다중 블러는 금지한다.
- 건물·도로는 청회색 무광 면, 네트워크는 날카로운 자기발광 선, 데이터는 거의 백색인 단단한 코어로 재질을 구분한다.
- 피격·위험 상태는 색 반전보다 형태 압축, 외곽선 두께, 방향성 예고를 우선한다.
- 정상 링크는 청록 실선, 교란 링크는 자홍 `8px/6px` 파선, 단절 링크는 회색 `10px/8px` 파선으로 색과 선 모양을 중복한다.
- 점멸은 초당 3회를 넘기지 않는다. 기본 교란 펄스는 1.5Hz이며, `reduced motion`에서는 알파 점멸 대신 파선 오프셋만 천천히 이동한다.

## 4. 캐릭터·적·환경·VFX 제작 방향

### 캐릭터와 적

- M1은 “도형을 조합한 벡터 스프라이트”로 직접 제작한다. 외부 캐릭터 팩의 화풍에 제품 정체성을 맞추지 않는다.
- 전달자는 얼굴이나 복식보다 방향성과 속도를 읽는 기체형 실루엣으로 시작한다. 인간형 디테일은 M3 이후 검토한다.
- 적의 몸체는 `city-500`과 `danger-red` 코어를 공통으로 사용하고 역할은 실루엣으로 구분한다. 역할별 무지개 팔레트는 쓰지 않는다.
- 일반 적은 32~48px, 파괴자·엘리트는 56~64px 안에서 유지한다. 플레이어보다 큰 적은 화면 면적이 아니라 명확한 예고 동작으로 위협을 표현한다.

### 환경

- 맵은 32px 논리 그리드를 사용하되 렌더링에서 격자선을 전부 노출하지 않는다.
- 주요 도로 폭은 96px 이상, 좁은 통로는 64px 이상으로 유지해 플레이어·적·투사체가 겹쳐도 읽히게 한다.
- 건물은 64px 단위의 모서리 잘린 블록, 장애물은 32px 또는 64px 모듈로 직접 제작한다. 지붕 설비와 폐차는 충돌이 없는 저대비 데칼로 분리한다.
- 후보 소켓, 본부, 패킷 캐시는 바닥 장식이 아니라 반복 가능한 랜드마크 키트로 만든다. 각각 화면 가장자리 지시자에서도 동일한 외곽형을 쓴다.
- 배경 디테일은 플레이 영역 평균 명도보다 10% 이상 밝아지지 않게 하고, 활성 링크 아래에는 강한 도로 선이나 간판을 두지 않는다.
- 도시 손상은 작은 쓰레기보다 큰 끊김, 비대칭 모서리, 2~3개의 균열 면으로 표현한다. 반복 타일 티를 숨기기 위한 노이즈 스프라이는 쓰지 않는다.

### VFX 상태 사전

| 사건 | 화면 효과 | 길이·규모 | 음향 짝 |
|---|---|---|---|
| 유효 연결 | 두 노드에서 만나며 완성되는 청록 선 + 작은 원형 파동 | 280ms, 반경 20px | 상승 2음 `network-connect` |
| 무효 설치 | 소켓 외곽이 주황에서 회색으로 접히고 짧은 X형 노치 | 180ms, 화면 흔들기 없음 | 낮은 이중 클릭 `place-invalid` |
| 링크 교란 | 링크에 자홍 파선이 덮이고 교란자에서 링크로 얇은 번개 1회 | 시작 220ms + 상태 파선 | 거친 디지털 플러터 `link-jammed` |
| 링크 단절 | 선이 중앙부터 양쪽으로 꺼지고 회색 잔선만 남음 | 240ms | 짧은 저역 차단음 `link-offline` |
| 패킷 회수 | 흰 마름모가 플레이어 코어로 접히며 4개 조각으로 흡수 | 320ms, 반경 28px | 유리성 상승음 `packet-pickup` |
| 업로드 완료 | 중계기→본부 방향으로 청록 펄스가 링크를 따라 이동 | 거리 기반 300~700ms | 3음 확인음 `upload-complete` |
| 대시 | 주황 평행 잔상 2개, 이동 방향 앞의 얇은 절개선 | 120ms, 잔상 최대 24px | 짧은 공기+전기음 `dash` |
| 적 사격 예고 | 사수와 목표 지점을 잇는 저알파 적색 선, 목표의 열린 브래킷 | 450~700ms | 방향성 틱 `shot-telegraph` |
| 추출 성공 | 본부 링이 닫히고 전체 망이 한 번 백색으로 순환 | 900ms, 플래시 20% 이하 | 네트워크 모티프의 완결 화음 |

화면 흔들기는 강한 피격과 파괴자 타격에만 2~4px, 80~140ms로 제한한다. 색수차, CRT 스캔라인, 글리치 오버레이는 기본 화면에 넣지 않고 결과·교란 전환의 짧은 효과로만 후보를 유지한다.

## 5. UI와 타이포그래피

### HUD 구조

- 좌상단: 체력과 과열. 막대보다 분절 캡슐을 사용해 값 변화가 주변시에서도 보이게 한다.
- 상단 중앙: 남은 시간. 2:00부터 주황 외곽, 0:30부터 적색 외곽으로 바뀌며 숫자 크기는 유지한다.
- 우상단: `업로드 0/3`, `탈출 잠김/가능`, 운반 중 패킷. 성공 조건을 가장 짧은 문장으로 표시한다.
- 하단 중앙: 대시, EMP, 상호작용 진행. 입력 아이콘은 기능 옆에 놓고 별도 범례로 떼지 않는다.
- 월드 UI: 중계기 내구도·업로드·수리는 대상 바로 위의 열린 링으로 표시한다. HUD와 월드 게이지를 동시에 중복 표시하지 않는다.
- 화면 가장자리 지시자: 패킷=마름모, 본부=잘린 정사각형, 끊긴 중계기=육각형. 색뿐 아니라 같은 외곽형을 유지한다.

패널은 불투명도 88% 이상의 어두운 면, 1~2px 외곽선, 잘린 8px 모서리로 통일한다. 작은 텍스트 뒤에 글로우를 사용하지 않는다. 본문은 최소 16px, 보조 수치는 14px, 핵심 타이머는 28~32px를 기준으로 한다.

### 글꼴

- 숫자·영문 제목·HUD 라벨: **Oxanium 500/600**. 각진 형태는 시스템 UI와 맞고 숫자 판독성이 좋다.
- 한글·본문·접근성 설명: **Noto Sans KR 400/600**. 한글을 Oxanium과 억지로 혼합하지 않고 폴백 기준선을 맞춘다.
- 런타임은 외부 CDN에 의존하지 않고 필요한 WOFF2만 로컬 번들한다. 폰트 로드 전에는 `system-ui, sans-serif`로 즉시 그린 뒤 로드 완료 시 한 번 다시 그린다.
- 글자 폭 변화로 HUD가 흔들리지 않도록 타이머와 수치에 고정 폭 영역을 주고 자리수를 고정한다. Canvas 글꼴에서 고정폭 숫자 기능을 보장할 수 없으면 숫자를 같은 너비의 셀에 한 글자씩 배치한다.

### 런타임 아틀라스 규격

| 종류 | 셀/캔버스 | 내용 경계 | 앵커 | 애니메이션 |
|---|---:|---:|---|---|
| 플레이어 | 64×64 | 최대 48×48 | 중앙 `(0.5, 0.5)` | idle 4f, thrust 4f, dash 2f, 12fps |
| 일반 적 | 64×64 | 32~48px | 중앙 | idle 2~4f, attack 3~5f, hit 2f, 10~12fps |
| 파괴자·엘리트 | 96×96 | 최대 72×72 | 중앙 | telegraph 포함 4~6f |
| 중계기·본부 | 96×96 / 192×192 | 반경 포함 | 중앙 | 코어·링을 별도 레이어로 회전 |
| 월드 타일 | 64×64 | 이음새까지 꽉 참 | 좌상단 | 정적, 변형 3개 이상 |
| 소형 프롭 | 32×32 / 64×64 | 셀당 4px 패딩 | 중앙 | 정적 |
| VFX | 64×64 / 128×128 | 셀당 4px 패딩 | 중앙 | 8~12f, 12~24fps |
| UI 아이콘 | 24×24 논리, 48×48 원본 | 4px 안전 패딩 | 중앙 | 정적 또는 2f 상태 |

- 직접 제작 원본은 SVG를 우선하고 래스터가 필요하면 2× PNG로 내보내 Canvas에서 절반 크기로 그린다.
- PNG는 sRGB, 투명 RGBA, 외곽 4px 투명 패딩을 유지한다. JPEG는 사용하지 않는다.
- 아틀라스는 최대 2048×2048, 셀 사이 4px extrude/padding을 둔다. 서로 다른 필터링·블렌드 모드의 자산을 한 아틀라스에 섞지 않는다.
- 방향은 북쪽 원본을 회전해 처리한다. 비대칭 무기나 읽기 문제가 검증된 경우에만 8방향 시트를 만든다.
- UI 아이콘은 24px 흑백 마스크에서도 식별되는지 먼저 확인한 뒤 색을 입힌다.

### 오디오 규격

| 단계 | 규격 |

| 원본·편집 마스터 | WAV, 48kHz, 24-bit; SFX mono, 음악 stereo |

## 8. 오디오 방향

### 음악

- 장르는 어두운 전자 앰비언트와 절제된 인더스트리얼 펄스의 중간이다. 영웅적 멜로디보다 “망이 살아 있는 기계”의 반복 리듬을 강조한다.
- M1은 반복 가능한 임시 트랙 1곡만 쓴다. 2분 검증에서 이동·사격·연결음을 덮지 않는 곡을 고르고, 다운로드 팩 전체를 포함하지 않는다.
- M2 이후 기본 레이어(저역 펄스), 압박 레이어(8분음표 하이햇·노이즈), 폭풍 레이어(154BPM 체감)를 분리한다. 링크 수와 남은 시간에 따라 크로스페이드하되 박자 중간에 트랙을 재시작하지 않는다.
- 메뉴는 별도 곡보다 런 모티프의 저역·드럼 제거 버전을 우선한다. 결과 화면은 성공 등급에 따라 같은 3음 네트워크 모티프의 마지막 음만 바꾼다.

### SFX 기능 사전

- 네트워크 계열은 `낮은 시작음 → 높은 확인음`을 공유한다. 연결은 완결, 업로드는 3음 확장, 단절은 같은 모티프를 역재생·저역화한다.
- 플레이어 계열은 짧고 건조한 주황색 느낌의 중역 펄스, 적은 거친 적색 노이즈와 낮은 기계음, 교란은 좁은 대역의 자홍 디지털 플러터로 구분한다.
- 중요한 예고음은 음악과 다른 중심 주파수와 리듬을 사용한다. 사수 예고, 링크 교란, 타이머 30초, 추출 시작은 화면 밖에서도 식별돼야 한다.
- 피격음은 적 종류보다 결과를 우선한다. 일반 적중, 방어막 적중, 플레이어 피해, 중계기 피해 네 묶음만 먼저 만든다.
- 화면 밖 사건은 약한 스테레오 방향성을 주되 헤드폰이 없어도 크기·필터 변화로 원근을 읽을 수 있게 한다.
- UI hover음은 만들지 않는다. 키보드 탐색과 메뉴 선택·확정·취소만 소리를 내어 플레이 중 SFX를 방해하지 않는다.

## 9. 폴더·파일명·라이선스 추적

다음 구조는 후속 에셋 편입 작업에서 생성한다. 이번 작업에서는 만들지 않는다.

```text
assets-src/
  art/{actors,environment,network,ui,vfx}/
  audio/{music,sfx}/
  vendor/<provider>-<pack>/
    LICENSE.txt
    SOURCE.json
    SHA256.txt
public/assets/
  sprites/{actors,environment,network,ui,vfx}/
  audio/{music,sfx}/
  fonts/
  data/asset-manifest.json
docs/licenses/
  ASSET-MANIFEST.yml
  CREDITS.md
```

### 파일명 규칙

- 전부 소문자 kebab-case, ASCII만 사용한다.
- 아트: `<domain>-<subject>-<state>-<direction>-<variant>-fNN.ext`
  - 예: `actor-courier-thrust-n-v01-f02.png`
  - 예: `network-relay-jammed-v01.svg`
  - 예: `vfx-upload-complete-v01-f07.png`
- 오디오: `music-<context>-<intensity>-loop-vNN.ogg`, `sfx-<system>-<event>-vNN.ogg`
  - 예: `music-run-pressure-loop-v01.ogg`
  - 예: `sfx-network-link-offline-v02.ogg`
- 폰트: `<family>-<subset>-<weight>.woff2`
  - 예: `oxanium-latin-600.woff2`, `noto-sans-kr-600.woff2`
- 외부 원본 파일명은 `assets-src/vendor/`에서 보존하고, 런타임 파일은 위 규칙으로 복사·변환한다. `SOURCE.json`의 `selectedFiles`와 `runtimeFiles`로 매핑한다.

### `SOURCE.json` 필수 필드

```json
{
  "id": "kenney-input-prompts",
  "title": "Input Prompts",
  "creator": "Kenney",
  "sourceUrl": "https://kenney.nl/assets/input-prompts",
  "retrievedAt": "YYYY-MM-DD",
  "version": "source-page version or retrieved date",
  "license": "CC0-1.0",
  "licenseUrl": "https://creativecommons.org/publicdomain/zero/1.0/",
  "attributionRequired": false,
  "commercialUse": true,
  "modificationAllowed": true,
  "selectedFiles": [],
  "runtimeFiles": [],
  "transformations": [],
  "archiveSha256": ""
}
```

### 편입 게이트

1. 원출처 페이지와 라이선스 파일을 사람이 열어 제목·제작자·라이선스를 확인한다.
2. 다운로드 원본의 SHA-256을 기록한다. 원본 ZIP 자체는 런타임 폴더에 넣지 않는다.
3. 필요한 파일만 선별하고 변환 내역, 새 파일명, 크레딧 문구를 `SOURCE.json`과 `ASSET-MANIFEST.yml`에 기록한다.
4. OFL 폰트의 저작권 문구와 `OFL.txt`를 배포물에 포함한다. CC0도 선택 크레딧을 `CREDITS.md`에 남긴다.
5. 출처 페이지가 사라지거나 라이선스 표기가 바뀌면 기존 기록과 해시를 검토하고 신규 다운로드를 중지한다.
6. 라이선스가 팩 설명과 내부 파일에서 다르면 더 제한적인 조건을 적용하는 대신 편입을 보류하고 별도 검토한다.

## 10. 첫 에셋 스프린트 — M1 2분 코어 증명

### 목표

한 화면에서 **이동 → 적 사격 회피 → 중계기 설치 → 패킷 업로드**가 설명 없이 읽히도록 하는 최소 에셋 세트를 만든다. 화려함보다 네트워크 상태 판독과 조작 피드백을 검증한다.

### 산출물

### 실행 순서

1. **라이선스·폰트·입력 표기 잠금**: `SOURCE.json`과 매니페스트를 먼저 만들고 P0 세트를 선별한다.
2. **흑백 판독성 패스**: 전달자, 적 2종, 중계기, 패킷, 본부를 색 없이 구현해 실루엣을 검수한다.
3. **환경·팔레트 패스**: 단일 M1 맵에 큰 도시 면과 기능 팔레트를 적용하고 링크보다 밝은 배경을 제거한다.
4. **HUD·상태 패스**: 정상·교란·단절, 설치 가능·불가, 운반·업로드를 색+형태+선 패턴으로 묶는다.
5. **VFX·오디오 패스**: 사건별 1개의 짧은 시각 효과와 음향을 연결하고 과한 잔광·동시 발음을 줄인다.
6. **통합 캡처 패스**: 아래 검수 장면을 실제 입력, 텍스트 상태 JSON, 스크린샷, 콘솔 로그와 함께 확인한다.

### 필수 검수 장면

- 시작 직후: 플레이어, 첫 패킷, 첫 소켓, 본부가 동시에 보이는 저압 장면
- 사수 예고 중 대시: 조준선, 플레이어 방향, 적 역할, 대시 잔상이 겹치는 장면
- 중계기 설치 가능/불가 비교: 같은 위치에서 입력 전후와 실패 피드백
- 정상·교란·단절 링크 3종: 컬러와 흑백 캡처 모두 저장
- 업로드 중 혼전: 진행 링, 적 탄환, 체력·과열, 패킷 수가 동시에 보이는 장면
- 30초 이하 귀환: 타이머 경고, 본부 지시자, 연결 경로가 서로 경쟁하지 않는 장면
- 960×540, 1280×720, 1920×1080에서 잘림·흐림·1px 소실 여부
- `reduced motion`과 음악·SFX·UI 음소거 조합

### 스프린트 완료 조건

- 흑백 화면에서도 플레이어, 패킷, 중계기, 적 2종과 링크 3상태를 구분한다.
- 청록=정상 연결, 주황=플레이어·소유, 자홍=교란, 백색=데이터, 적색=피해 의미가 전 장면에서 깨지지 않는다.
- 핵심 HUD 본문은 16px 이상이며, 타이머·패킷·탈출 가능 여부가 시선 이동 한 번 안에 읽힌다.
- 네트워크 연결·교란·단절·업로드 완료를 화면 없이도 서로 다른 소리로 구분한다.
- 선택한 모든 외부 파일에 원출처, 라이선스, 해시, 변환, 런타임 파일 매핑이 있다.
- 실제 플레이 스크린샷이 `render_game_to_text()`의 상태와 일치하고 콘솔에 새 오류가 없다.
- `npm run check`, `npm run build`, 플레이 검증 시나리오가 성공한다.

## 11. 범위 밖과 재검토 신호

- M1에서는 8방향 인간형 애니메이션, 초상화, 스토리 일러스트, 날씨, 풀스크린 후처리, 보스 VFX, 다중 바이옴을 만들지 않는다.
- 외부 도시 타일셋은 직접 제작한 64px 모듈로 공간 읽기가 부족하다는 플레이테스트 증거가 있을 때만 재검토한다.
- 커스텀 음악 제작은 임시 CC0 트랙이 상태 SFX를 반복해서 가리거나 M2의 동적 압박 레이어를 만들 수 없을 때 시작한다.
- 픽셀 아트 전환, 사실적 인물, 카메라 회전, 3D 조명은 아트 조정이 아니라 제품 방향 변경이므로 ADR 대상이다.
- 화면이 밋밋하다는 이유로 글로우와 파티클을 늘리지 않는다. 먼저 링크·목표·위험의 크기, 명도, 여백 계층을 조정한다.
