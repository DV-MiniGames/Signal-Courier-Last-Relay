## 2. 선택 근거

현재 하네스는 단일 Canvas에서 실행, 입력, 전체 화면, 상태 JSON, 수동 시간 진행과 Playwright 검증을 이미 통과했다. M1은 한 맵과 소수 도형·스프라이트로 핵심 가설을 검증하므로 Phaser·PixiJS·Godot으로 옮길 이익보다 마이그레이션과 자동화 재구축 비용이 크다. 게임 규칙을 브라우저와 분리하고 renderer port를 두어 Canvas 한계가 실제 계측으로 확인될 때 PixiJS를 첫 대안으로 검토한다.

외부 그래픽 팩을 그대로 사용하면 SIGNAL COURIER: LAST RELAY의 정체성과 기능 색 체계가 약해진다. 따라서 플레이어, 적, 중계기, 패킷, 도시 모듈, 링크와 상태 VFX는 Canvas 도형 또는 프로젝트 소유 원본으로 만든다. 입력 글리프, 글꼴, 원재료 SFX와 임시 음악만 검증된 무료 출처를 사용한다.

## 3. 에셋 획득 결정

사전 제작 단계에서는 바이너리를 다운로드하지 않았다. M1 구현에서 아래 순서로 필요한 파일만 편입한다.

### 직접 제작

- 플레이어·적 2종의 실루엣과 방향·위험 표식
- 본부, 중계기, 소켓, 패킷과 연결 3상태
- 64px 폐도시 모듈, 충돌·엄폐·통로 형태
- 사격, 대시, EMP, 업로드, 교란, 단절, 추출 VFX

## 4. M1 실행 순서

한 번에 한 작업만 Doing으로 두고 다음 순서를 지킨다.

1. **도구·구조 보존** — Claude 접근을 확인한다. 가능하면 Claude, 불가하면 Codex가 현행 45초 게임을 순수 코어와 브라우저 어댑터로 분리한다. 화면과 상태 계약은 바꾸지 않는다.
2. **결정론 잠금** — Vitest 4.1.11, 고정 tick, 잔여 시간 accumulator, seed PRNG, 입력 프레임, canonical hash를 추가한다.
3. **2분 코어 구현** — 이동·대시·조준 사격·EMP, 추격자·사수, 중계기 1개, 패킷 1개, 업로드를 한 흐름으로 만든다.
4. **기능 아트** — 직접 제작한 실루엣과 기능 팔레트로 링크 정상·교란·단절을 색과 형태로 함께 표시한다.
5. **보조 에셋 편입** — P0 입력 글리프·폰트부터 라이선스 게이트를 통과시킨다. SFX·음악은 핵심 상태 판독에 필요한 최소 수량만 P1로 넣는다.
6. **통합 검증** — 동일 seed 재현, 실제 입력, 텍스트 상태, 필수 장면 스크린샷, 콘솔 오류, `check/test/build/test:game`을 확인한다.

## 5. M1 종료 조건

- 신규 테스트 5명 중 4명이 설명 없이 2분 안에 중계기를 연결하고 패킷을 업로드한다.
- 중계기 위치가 전투 공간 또는 귀환 경로를 바꾼다고 테스트 참가자가 인식한다.
- 같은 seed와 tick 입력을 10회 실행해 같은 canonical hash를 얻는다.
- 실제 rAF와 `advanceTime`이 같은 step 함수를 사용하며 0ms는 상태를 바꾸지 않는다.
- 정상·교란·단절 링크가 흑백에서도 선 형태로 구분된다.
- 모든 외부 파일에 원출처, 라이선스, 해시, 변환과 런타임 매핑이 있다.
- `npm run check`, `npm run test:unit`, `npm run build`, `npm run test:game`이 성공하고 새 콘솔 오류가 없다.
- 960×540, 1280×720, 1920×1080 필수 장면에서 잘림·흐림·핵심 정보 누락이 없다.

## 6. 결정 게이트

- M1에서 연결의 경로 가치가 검증되지 않으면 적·맵 콘텐츠를 늘리지 않고 소켓, 연결 반경, 업로드 위치를 재설계한다.
- Canvas render p95가 최적화 후에도 8ms를 두 차례 넘거나 250개 이상 움직이는 sprite가 필수가 되면 PixiJS 1일 spike를 연다.
- 두 번째 이상 맵과 tilemap·animation·physics 제작량이 M1의 3배 이상이고 Phaser가 세 모듈 이상을 제거할 때만 Phaser ADR을 검토한다.
- 브라우저가 1차 플랫폼이 아니거나 다수 레벨을 시각 에디터에서 제작해야 할 때만 Godot 포팅을 검토한다.
- 장르, 탑다운 카메라, 10분 하드 캡, 데스크톱 웹, 기능 팔레트 변경은 모두 ADR과 일정 재산정 대상이다.
