# Signal Courier 사전 제작 게임 디자인 확정안

- 문서 상태: Preproduction Lock v1.0
- 연결 작업: `TASK-20260830-02` 최종 게임 콘셉트 결정
- 작성·조사일: 2026-08-30 (KST)
- 제품 한 줄: **붕괴하는 도시망에 중계기 사슬을 놓고 데이터를 회수한 뒤, 10분 안에 살아서 귀환하는 2D 탑다운 액션·경로 설계 로그라이트**

## 1. 확정 제품 방향

| 항목 | 결정 |
|---|---|
| 장르 | 싱글 플레이 탑다운 액션·경로 설계 로그라이트, 가벼운 익스트랙션 구조 |
| 플레이어 판타지 | 전투원이 아니라, 총격 속에서도 연결 경로를 만들어 임무를 끝내는 최후의 신호 전달자 |
| 카메라 | 2D 탑다운 추적 카메라. 전투 판독성을 위해 회전하지 않는다. |
| 한 판 길이 | 활성 플레이 최대 10분, 목표 중앙값 8분. 2개 패킷부터 조기 탈출, 3개 패킷으로 완전 성공. |
| 타깃 플랫폼 | 데스크톱 웹, 최신 Chromium 계열 브라우저, 키보드+마우스 우선 |
| 기술 기준선 | Vite + TypeScript + 단일 Canvas 2D. `render_game_to_text`와 `advanceTime` 계약 유지 |
| 아트 방향 | 어두운 폐도시 위의 고대비 레트로 퓨처 벡터 그래픽. 청록 연결망, 주황 플레이어, 자홍 교란, 백색 데이터로 기능 색을 고정한다. |
| 상품 범위 | 설치·계정·서버 없이 바로 시작하는 로컬/웹 MVP. 세션 숙련과 짧은 재도전을 우선한다. |

이 게임은 현재 45초 노드 수집 마이크로게임의 감각을 계승하지만, 단순 접촉 수집을 최종 제품으로 확장하지 않는다. 최종 핵심은 **어디로 움직일지**, **어디에 중계기를 남길지**, **언제 교전을 끊고 탈출할지**가 하나의 판단으로 이어지는 것이다.

## 2. 타깃 플레이어

### 1차 타깃

- 20~40대 PC 액션 인디 게임 플레이어
- 10~20분 공백에도 완결된 한 판을 원하는 플레이어
- 정밀 조준만큼 경로 최적화, 위험 관리, 빌드 선택에서 숙련감을 느끼는 플레이어
- 반복 플레이를 좋아하지만 긴 파밍, 복잡한 인벤토리, 지식 장벽은 부담스러운 플레이어

### 플레이 요구

- 첫 판 60초 안에 “패킷 회수 → 연결된 중계기에 업로드 → 본부에서 탈출”을 이해해야 한다.
- 한 판의 실패 이유가 난수보다 경로, 지연, 교전 지속, 탈출 판단으로 설명되어야 한다.
- 능숙해질수록 사격 수치가 아니라 더 짧고 안전한 연결망과 더 과감한 추가 회수로 차이가 나야 한다.

### 타깃이 아닌 플레이어

- 장시간 캠페인과 대사 중심 서사를 주목적으로 찾는 플레이어
- 사실적 탄도, 장비 등급 파밍, 슬롯형 인벤토리를 기대하는 하드코어 익스트랙션 슈터 플레이어
- 멀티플레이 경쟁·협동 또는 방치형 성장을 핵심으로 기대하는 플레이어

## 3. 디자인 기둥

### 기둥 A — 경로가 곧 빌드다

중계기는 체크포인트가 아니다. 배치 위치가 데이터 업로드 지점, 회복 구역, 대시 재충전, 적의 공격 목표, 귀환 경로를 동시에 바꾼다. 런 종료 화면은 무기 DPS보다 먼저 플레이어가 만든 연결망을 보여준다.

### 기둥 B — 전투는 시간을 사는 수단이다

적 처치 자체는 핵심 보상이 아니다. 필요한 적만 밀어내고 패킷을 업로드하거나 끊어진 링크를 복구하는 것이 더 좋은 플레이일 수 있다. 무한 처치 파밍은 만들지 않는다.

### 기둥 C — 안전한 성공과 욕심의 경계가 선명하다

패킷 2개를 확보하면 탈출할 수 있다. 세 번째 패킷과 추가 과부하 데이터는 더 큰 보상을 주지만 남은 시간, 체력, 중계기 상태를 함께 걸게 한다. 탈출 가능 여부와 잃을 보상은 HUD에서 항상 보인다.

### 기둥 D — 10분 안에 읽고, 결정하고, 다시 도전한다

런은 10분에 강제로 끝난다. 적 체력 증가보다 새로운 조합과 공간 압박으로 난도를 올리고, 사망 후 30초 안에 같은 시드 재도전 또는 새 시드 시작이 가능해야 한다.

## 4. 핵심 플레이 루프

### 세션 루프

1. 본부에서 무기 1개, 유틸리티 1개, 중계기 모듈 1개를 선택한다.
2. 임무 시드와 세 패킷 후보 위치를 5초간 확인한다.
3. 중계기 사슬을 확장하며 패킷을 회수·업로드한다.
4. 2개 패킷 이후 안전한 부분 탈출과 세 번째 패킷 도전 중 하나를 고른다.
5. 본부로 귀환해 8초 동안 추출 신호를 유지한다.
6. 확보한 기록으로 수평형 장비와 변형 계약을 해금하고 즉시 다음 런을 선택한다.

### 10분 런의 목표 리듬

| 시간 | 플레이 의도 | 시스템 변화 | 플레이어 결정 |
|---:|---|---|---|
| 0:00~1:00 | 방향 파악과 첫 성공 | 추격자만 출현, 첫 패킷은 안전한 후보군에 배치 | 가까운 패킷과 첫 중계기 가지 선택 |
| 1:00~3:00 | 첫 사슬 완성 | 첫 업로드 후 런 내 강화 1회 | 전투·이동·망 강화 중 하나 선택 |
| 3:00~6:00 | 경로 분기와 압박 | 사수와 교란자 합류, 두 번째 업로드로 탈출 개방 | 지금 귀환할지 외곽으로 더 나갈지 판단 |
| 6:00~8:30 | 완전 성공 도전 | 파괴자가 중계기를 직접 공격, 정전 구역 확대 | 사슬을 수리할지 우회해 세 번째 패킷을 밀지 판단 |
| 8:30~10:00 | 귀환과 최종 방어 | 폭풍 단계, 본부 추출 8초 채널링 | 추가 과부하 데이터를 포기하고 탈출할 시점 결정 |

- 10:00에 폭풍이 맵을 덮는다. 추출 채널링 중이어도 완료되지 않았으면 런은 실패한다.
- 목표 런 분포는 부분 탈출 6~8분, 완전 탈출 8~9분 30초, 실패 최대 10분이다.
- 컷신과 결과 화면은 활성 타이머에 포함하지 않되 각각 10초 이내로 유지한다.

## 5. 시스템 설계

### 5.1 이동

- `WASD`로 즉각 반응하는 8방향 이동을 사용한다. 관성, 스태미나, 낙하 피해는 없다.
- `Space` 대시는 짧은 무적 구간과 적 관통을 제공한다. 기본 재사용 대기시간은 1.6초를 초기값으로 둔다.
- 활성 중계기 반경에서는 대시 재충전과 무기 냉각이 빨라진다. 따라서 플레이어가 만든 사슬은 실제 이동 리듬을 바꾼다.
- 충돌물은 “통과 가능”, “완전 차단”, “적 투사체만 차단”의 세 부류만 사용한다. 작은 장식물 충돌은 두지 않는다.
- 카메라는 플레이어를 따라가되 이동 방향으로 약하게 선행한다. 목표, 연결선, 적 투사체가 화면 가장자리에서 예고되어야 한다.

### 5.2 전투

전투의 목표는 섬멸이 아니라 **업로드·수리·귀환에 필요한 공간 확보**다.

- 기본 무기 `펄스 블래스터`: 마우스로 조준하고 좌클릭으로 발사한다. 탄약 대신 과열을 사용해 재장전 인벤토리를 없앤다.
- 기본 유틸리티 `EMP 펄스`: 우클릭으로 근거리 적을 밀치고 교란 충전을 끊는다. 긴 재사용 대기시간으로 결정적 순간에 사용한다.
- 대시는 공격 취소와 탈출 수단이지만 피해를 주지 않는다.
- 일반 적 처치는 영구 재화를 드롭하지 않는다. 소량의 임시 냉각 또는 체력 조각만 주어 무한 사냥 동기를 막는다.
- 패킷 업로드마다 세 선택지 중 하나의 런 내 강화를 고른다. 강화 축은 `화력`, `기동`, `망`으로 고정해 빌드 의도를 읽기 쉽게 한다.

적 역할은 네 가지로 제한한다.

| 적 | 역할 | 대응 학습 |
|---|---|---|
| 추격자 | 플레이어를 근접 압박 | 이동·대시 타이밍 |
| 사수 | 이동 예정 지점에 예고탄 발사 | 경로 전환과 엄폐 |
| 교란자 | 가까운 링크를 잠시 차단하는 충전 공격 | 우선 표적 선택과 EMP |
| 파괴자 | 플레이어보다 중계기를 우선 공격 | 지킬 망과 버릴 망의 선택 |

MVP 엘리트는 기존 적 두 역할을 결합하되 새로운 규칙을 추가하지 않는다. 체력만 늘리는 변종은 만들지 않는다.

### 5.3 중계기

- 맵에는 육안으로 구분되는 후보 소켓 6개가 있고, 플레이어는 접이식 중계기 3개를 들고 시작한다.
- 중계기는 본부 또는 이미 활성화된 중계기의 연결 반경 안에 있는 소켓에만 설치할 수 있다. 유효·무효 연결을 색과 선 모양으로 동시에 표시한다.
- 설치는 `E`를 1초 유지한다. 연결이 끊기거나 잘못 놓였으면 다시 회수할 수 있어 한 번의 실수로 런이 확정 실패하지 않는다.
- 활성 중계기는 업로드 지점이자 작은 안전 구역이다. 기본 효과는 무기 냉각과 대시 재충전 보조이며, 선택 모듈이 방어막·감속장·수리 중 하나를 더한다.
- 중계기 내구도가 0이 되면 파괴되지 않고 오프라인이 된다. 2초 수리로 복구할 수 있지만, 그동안 하위 링크와 업로드 기능은 정지한다.
- 확보한 패킷은 활성 중계기에서 3초 동안 업로드하면 영구 확보된다. 업로드는 적을 유인하고 피격 시 진행이 잠시 멈추지만 처음부터 초기화되지는 않는다.
- 연결선은 장식이 아니라 상태 UI다. 정상은 청록 실선, 교란은 자홍 점멸, 단절은 회색 파선으로 표시하고 `render_game_to_text`에도 같은 상태를 노출한다.

중계기 설계의 핵심 질문은 “어디에 버프 지대를 놓을까?”가 아니라 “지금 확장한 이 길을 나중에 살아서 되돌아올 수 있는가?”다.

### 5.4 패킷과 임무

- 맵 외곽의 기본 데이터 캐시 3개가 주목표다. 별도의 선택형 과부하 캐시 2개가 있으며, 매 런 위치 조합은 시드로 바뀌지만 후보 소켓과 장애물은 손으로 설계한다.
- 한 번에 패킷 1개만 운반한다. 운반 중 피격은 패킷을 잃게 하지 않지만 플레이어 위치를 적에게 주기적으로 노출한다.
- 패킷 1개 업로드: 런 내 강화 선택과 기록 조각 1개 확보.
- 패킷 2개 업로드: 본부 추출 개방, 부분 성공 자격 획득.
- 패킷 3개 업로드: 완전 성공 자격과 보너스 기록 조각 획득.
- 세 번째 이후 선택형 외곽 캐시에서 `과부하 데이터`를 회수할 수 있다. 이는 추출해야만 보존되며 시간 욕심을 만드는 선택 보상이다.

### 5.5 탈출과 결과

- 탈출은 본부에서만 시작한다. 귀환 경로를 생략하는 즉시 탈출 아이템은 MVP에 넣지 않는다.
- 본부에서 `E`를 유지하면 8초 추출이 시작된다. 이동하면 진행이 멈추지만 누적치는 2초 동안 유지되어 짧은 회피를 허용한다.
- 연결된 중계기 수에 따라 본부 방어막이 강해진다. 살아 있는 사슬을 유지한 플레이가 최종 방어에서 보상된다.
- 결과 등급은 `실패(0~1개 또는 미탈출)`, `부분 전달(2개+탈출)`, `완전 전달(3개+탈출)` 세 가지뿐이다.
- 이미 업로드한 기본 기록 조각은 실패해도 보존한다. 과부하 데이터와 성공 보너스는 탈출하지 못하면 잃는다. 실패해도 배움은 남고, 욕심에는 명확한 손실이 생긴다.

## 6. 메타 진행

메타의 목적은 반복 작업으로 수치를 쌓는 것이 아니라 다음 런의 **새로운 판단 도구**를 여는 것이다.

### 재화와 해금

- 단일 재화 `기록 조각`만 사용한다. 업로드한 기본 패킷은 즉시 보존하고 탈출 등급으로 보너스를 준다.
- 영구 `공격력 +5%` 같은 누적 스탯은 만들지 않는다.
- 해금은 시작 무기 변형, 유틸리티, 중계기 모듈, 임무 계약처럼 플레이 방식을 바꾸는 수평 선택지로 제한한다.
- 첫 3런 안에 최소 1개 해금, 이후 2~3런마다 1개 해금을 목표로 한다. 동일 콘텐츠를 반복해야만 기본 완주가 가능한 비용 곡선은 금지한다.

### MVP 해금 풀

- 시작 무기 2종: 기본 펄스 블래스터, 근거리 연쇄형 아크 발사기
- 유틸리티 2종: 기본 EMP, 적 시선을 끄는 홀로 비콘
- 중계기 모듈 3종: 방어막, 적 감속장, 자동 수리
- 계약 3종: 시간 단축, 중계기 1개 감소, 교란자 강화. 보상 배율과 함께 위험을 사전에 명시한다.

### 장기 확장 원칙

새 구역은 적 체력과 숫자만 바꾸지 않고 연결 규칙을 하나씩 변주한다. 예를 들어 가동식 소켓, 주기적 정전, 단방향 링크를 한 구역에 하나만 도입한다. 새 캐릭터, 장비 등급, 제작 재료는 기본 루프가 검증된 뒤 별도 결정으로 다룬다.

## 7. 난이도 곡선

난도는 시간과 임무 진척의 두 축으로 오른다. 시간은 압박을 예측 가능하게 만들고, 패킷 진척은 플레이어가 스스로 다음 파동을 당겼다는 책임감을 만든다.

| 단계 | 시간/진척 | 위협 구성 | 설계 목표 |
|---|---|---|---|
| 온보딩 | 0~2분, 0패킷 | 소수 추격자, 넓은 예고 | 이동·사격·첫 설치 성공 보장 |
| 긴장 | 2~5분, 1패킷 | 사수 추가, 두 방향 압박 | 안전 구역과 외곽 사이 왕복 학습 |
| 결정 | 5~7분, 2패킷 | 교란자와 혼합 파동 | 부분 탈출과 완전 성공의 선택 |
| 붕괴 | 7~9분, 3패킷 도전 | 파괴자, 끊어진 링크, 좁아지는 안전 구역 | 구축한 경로의 가치 시험 |
| 폭풍 | 9~10분 | 빠른 혼합 파동, 명확한 전면 경고 | 전투보다 귀환·탈출 우선 |

- 적 최대 체력은 런 시작 대비 약 1.6배를 넘기지 않는다. 난도는 동시 역할 수, 공격 각도, 링크 압박으로 높인다.
- 화면 내 일반 적 상한과 투사체 상한을 둔다. 상한 초과 예산은 엘리트 승격이나 다음 파동 지연으로 처리한다.
- 첫 패킷 위치와 첫 중계기 후보는 항상 안전 규칙을 만족한다. 실패 시드가 생성되지 않게 시드 검증을 자동화한다.
- 표준 난도를 기준으로 조정하고, MVP 검증 후 피해량·시간·조준 보조를 독립 조정하는 접근성 옵션을 추가한다. 색만으로 상태를 구분하지 않고 화면 흔들기와 점멸 강도는 끌 수 있게 한다.

## 8. MVP 범위

### 포함

- 손으로 설계한 폐도시 맵 1개, 데이터·적 배치 시드 최소 3개
- 플레이어 1명, 이동·대시·조준 사격·EMP
- 기본 패킷 3개, 선택형 과부하 캐시 2개, 중계기 후보 6개, 휴대 중계기 3개, 연결·교란·수리 상태
- 일반 적 4종, 조합형 엘리트 1종, 시간·진척 기반 디렉터
- 부분/완전 탈출과 10분 하드 캡
- 런 내 강화 축 3개, 메타 해금 7개, 변형 계약 3개
- 시작 화면, 조작 안내, HUD, 결과 화면, 로컬 저장
- 메뉴·플레이·일시정지·재시작·전체 화면과 기존 자동화 계약
- 입력 → 중계기 설치 → 패킷 업로드 → 부분/완전 탈출을 검증하는 결정론적 시나리오와 실제 스크린샷
- 기능 중심의 합성 효과음과 고대비 벡터 임시 아트

### 명시적 제외

- 멀티플레이, 순위표, 계정, 클라우드 저장, 백엔드
- 절차 생성 지형, 맵 에디터, 캠페인 월드맵, 분기 서사
- 차량, 물리 기반 화물 적재, 스태미나·허기·탄약 인벤토리
- 장비 희귀도, 제작, 상점 경제, 다중 재화, 반복 스탯 성장
- 보스전, 동료, 펫, 플레이어 클래스 다수
- 모바일·터치, 콘솔 인증, 게임패드 정식 지원
- 최종 일러스트, 성우, 라이선스 음악, 배포·수익화 기능

범위 압력이 생기면 메타 콘텐츠 수를 먼저 줄이고, 이동-전투-중계기-탈출의 한 런 흐름은 줄이지 않는다.

## 9. 성공 지표와 MVP 통과 기준

### 플레이어 이해와 재미

| 지표 | MVP 목표 | 측정 방법 |
|---|---:|---|
| 첫 패킷 목적 이해 | 신규 플레이어 80%가 설명 없이 60초 안에 첫 패킷을 향함 | 10명 이상 첫 플레이 관찰 |
| 첫 연결 성공 | 80%가 2분 안에 중계기 설치·연결·업로드 수행 | 이벤트 로그와 화면 녹화 |
| 경로 선택 체감 | 70%가 “중계기 위치가 귀환/전투에 영향을 줬다” 4/5 이상 응답 | 3런 후 설문 |
| 탈출 판단 | 70%가 3런 안에 부분 탈출과 완전 성공 중 의식적 선택을 1회 이상 함 | 결과·경로 로그와 사후 질문 |
| 재도전 의향 | 60%가 첫 실패/성공 후 30초 안에 다음 런 시작 | 세션 로그 |

### 밸런스와 품질

| 지표 | MVP 목표 | 측정 방법 |
|---|---:|---|
| 런 길이 | 중앙값 7~9분, 모든 활성 런 10분 이내 | 런 시작·종료 이벤트 |
| 표준 난도 완전 탈출률 | 첫 3런 30~50%, 10런 경험자 60~80% | 플레이테스트 코호트 |
| 실패 원인 편중 | 시간 초과·체력 0·탈출 실패 중 어느 하나도 전체 실패의 70% 초과 금지 | 결과 이벤트 |
| 판독성 | 신규 플레이어 90%가 연결/교란/단절 상태를 정답으로 구분 | 정지 화면 테스트 |
| 성능 | 기준 PC의 Chromium에서 활성 플레이 p95 프레임 20ms 이하 | 브라우저 성능 로그 |
| 회귀 증거 | 플레이 변경 100%가 입력, 텍스트 JSON, 스크린샷, 콘솔 오류 검사를 포함 | 작업 기록 |

완전 탈출률이 낮다는 이유만으로 영구 스탯을 추가하지 않는다. 먼저 첫 경로 길이, 적 역할 도입 시점, 업로드 중단 규칙을 조정한다.

## 10. 4단계 마일스톤

| 단계 | 산출물 | 종료 조건 | 다음 단계로 넘기지 않을 위험 |
|---|---|---|---|
| M0 — 방향 잠금 | 이 문서, 화면 흐름, 핵심 이벤트 목록, 회색상자 맵 | 본 문서를 제작 기준선으로 채택하고 첫 런 테스트 시나리오 작성 | 핵심 루프가 “노드 수집+사격”으로만 읽히는 문제 |
| M1 — 2분 코어 증명 | 이동·사격·대시, 적 2종, 중계기 1개, 패킷 1개 업로드 | 신규 테스트 5명 중 4명이 설명 없이 연결과 업로드 성공; 자동 상태와 화면 일치 | 중계기 설치가 전투·귀환 경로를 바꾸지 못함 |

각 단계는 플레이 가능한 수직 조각으로 끝난다. M1에서 중계기의 경로 가치가 검증되지 않으면 콘텐츠를 추가하지 않고 시스템을 축소·재설계한다.

## 12. 유사작 조사와 차별화

조사는 패턴을 확인하기 위한 것이며 기능·레이아웃·표현을 복제하기 위한 것이 아니다.

| 레퍼런스 | 확인한 장르 패턴 | Signal Courier에 취할 것 | 취하지 않을 것 / 차별점 |
|---|---|---|---|
| DEATH STRANDING DIRECTOR'S CUT | 지형과 주문 조건을 보고 경로를 준비하며, 설치물이 이후 이동을 돕는다. | 이동 전에 경로를 읽고 현장에 연결 기반을 남기는 전달자 판타지 | 사실적 화물 물리, 광대한 오픈 월드, 비동기 소셜 구조를 제외한다. 중계기는 한 런의 전투·귀환 경로를 즉시 바꾼다. |
| Pacific Drive | 거점에서 경로를 준비하고, 현장 자원으로 업그레이드와 탈출을 수행한 뒤 거점으로 돌아온다. | 준비-출동-위험 상승-귀환의 명료한 세션 구조 | 차량 정비, 제작, 장시간 생존 탐사를 제외한다. 준비 20초, 활성 런 10분으로 압축한다. |
| Risk of Rain 2 | 시간이 흐를수록 적과 플레이어가 함께 강해져, 파밍과 진행 속도를 저울질한다. | 항상 보이는 시간 압박과 늦을수록 복합해지는 위협 | 무한 성장과 장시간 생존을 제외한다. 강제 10분 종료, 목표 업로드 기반 강화로 전투 파밍을 억제한다. |
| Hades | 영구 진행과 난이도 변형이 반복 런의 동기를 보완한다. | 런 밖 수평 해금과 사전 고지된 변형 계약 | 서사 허브 규모, 누적 능력치 의존, 방 단위 전투를 제외한다. 한 장의 공간에 플레이어가 만든 망이 남는다. |
| ZERO Sievert | 탑다운 전투에서 자원을 회수하고 살아서 돌아와야 획득의 의미가 생긴다. | 추출 가능 상태와 손실 가능 보상을 명확히 보여주는 긴장 | 인벤토리 테트리스, 탄약 경제, 절차 생성 생존 시뮬레이션을 제외한다. 기본 기록은 업로드 시 보존해 실패 비용을 제한한다. |
| Dome Keeper | 제한된 시간에 외부 자원을 얻는 일과 거점 방어로 돌아오는 일이 충돌한다. | 떠날 시간과 돌아올 시간을 동시에 계산하는 압박 | 채굴/방어의 분리된 페이즈와 고정 포탑 조작을 제외한다. 이동·전투·망 구축을 끊김 없이 한 공간에서 수행한다. |

### 핵심 차별점

1. **중계기 사슬이 목적, 체크포인트, 이동 버프, 적의 표적, 탈출 방어력을 동시에 결정한다.** 비교작의 길·거점·텔레포터 요소를 조합하는 데 그치지 않고 한 상태 모델로 묶는다.
2. **익스트랙션의 긴장을 10분 하드 캡과 부분 성공으로 압축한다.** 장비 파밍 손실 대신 더 멀리 확장한 연결망과 과부하 데이터만 위험에 건다.
3. **런의 기록은 처치 수보다 네트워크 지도다.** 결과 화면에서 배치 순서, 단절 시점, 패킷 귀환 경로를 재생해 학습과 재도전의 근거로 삼는다.

## 14. 제작 판단 원칙

- 플레이테스트에서 문제가 생기면 10분 제한을 늘리기보다 이동 거리와 상호작용 시간을 먼저 줄인다.
- 콘텐츠 부족을 메타 수치 성장으로 가리지 않는다.
- 새 기능은 이동, 전투, 중계기, 탈출 중 최소 두 시스템의 판단을 연결할 때만 MVP 후보가 된다.
- 스크린샷과 텍스트 상태가 다르면 화면을 실제 결과로 보고 수정한다.
- 이 방향의 장르, 카메라, 런 길이, 플랫폼, 아트 방향을 바꾸는 제안은 구현 중 범위 확장이 아니라 ADR 대상이다.
