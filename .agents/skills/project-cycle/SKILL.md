# Project Cycle

## When to Use

- 새 작업을 시작하거나 완료 상태로 전환할 때
- 작업 결과에서 재사용 가능한 교훈을 추출할 때
- 주간 운영 리뷰에서 프로세스와 스킬을 개선할 때

## Procedure

1. `ops/CHARTER.md`, `ops/BOARD.md`, `ops/MEMORY.md`를 순서대로 확인한다.
2. 관련 작업 ID를 찾는다. 없으면 `ops/tasks/TEMPLATE.md`에서 실행 작업을 만든다.
3. 작업이 Ready 조건을 충족하는지 확인한다.
4. 작업을 Doing으로 옮기고 WIP 제한을 확인한다.
5. 가장 작은 검토 가능한 단위로 실행한다.
6. 작업에 정의된 방법으로 결과를 검증하고 증거를 기록한다.
7. 완료 조건, 문서 갱신, 남은 위험을 확인한 뒤 Done으로 옮긴다.
8. 학습 후보를 `폐기`, `작업 기록`, `결정`, `메모리`, `스킬 후보`로 분류한다.
9. 유사 절차가 두 번 이상 성공했다면 새 스킬을 만들거나 기존 스킬을 패치한다.

## Pitfalls

- 검증 방법이 없는 작업을 Ready로 이동하지 않는다.
- Doing 작업이 남아 있는 상태에서 새 작업을 시작하지 않는다.
- 일회성 로그나 쉽게 다시 찾을 수 있는 사실을 메모리로 승격하지 않는다.
- 한 번 성공한 요령을 즉시 독립 스킬로 만들지 않는다.
- 프로세스 문제를 개인 평가 지표로 사용하지 않는다.
- 오래된 스킬을 즉시 삭제하지 않고 stale과 archived 단계를 거친다.

## Verification

- 운영 보드의 모든 Doing 작업에 담당자와 작업 기록 링크가 있다.
- Done 작업마다 완료 조건과 검증 증거가 있다.
- 새 메모리 항목마다 출처가 있고 여러 작업에서 재사용할 가치가 있다.
- 새 스킬은 두 번 이상의 성공 근거와 명시적인 검증 절차를 가진다.
- 주간 리뷰에는 다음 주에 시험할 개선 실험이 정확히 하나 있다.
