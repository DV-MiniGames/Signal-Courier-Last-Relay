# 게임 프로젝트 실행 규칙

## 세션 시작

1. `ops/CHARTER.md`, `ops/BOARD.md`, `ops/METRICS.md`, `ops/MEMORY.md` 순서로 읽는다.
2. 현재 빌드, Git 상태, 실행 명령과 관련 작업 기록을 확인한다.
3. 모든 실행을 하나의 작업과 연결하고, 실행 주체당 Doing은 하나만 둔다.

## 구현

- 가장 위험한 플레이 가설을 작은 수직 조각으로 먼저 검증한다.
- 장르, 플랫폼, 엔진, 핵심 루프와 아트 방향 변경은 결정 기록을 남긴다.
- 새 조작과 상태는 게임 화면, 조작 문서와 자동화 상태에 함께 반영한다.
- 외부 에셋은 출처·라이선스·해시·변환 기록 없이는 반입하지 않는다.

## 완료

- 정적 검사와 production build가 성공한다.
- 플레이 변경은 실제 입력, 중간·결과 상태, 화면과 오류를 확인한다.
- 사운드 변경은 실제 청취 또는 사건 시점 측정을 추가한다.
- 사람의 이해·재미·난도는 자동화로 통과 처리하지 않는다.
- 작업 기록, 보드, 위험과 다음 행동을 갱신한다.

## 학습

- 사건은 작업 기록, 장기 선택은 결정 기록, 여러 작업에 필요한 사실은 메모리에 둔다.
- 두 번 이상 성공하고 검증 방법이 있는 절차만 스킬 후보로 승격한다.
