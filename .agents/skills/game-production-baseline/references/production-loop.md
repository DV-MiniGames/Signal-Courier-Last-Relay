# 제작 단계와 게이트

단계는 선형 일정이 아니라 증거를 쌓는 순서다. 실패하면 직전 가설로 돌아가며, 콘텐츠를 더 추가해 문제를 덮지 않는다.

## 0. 저장소와 권한 정렬

- 기존 저장소 확인: 지침, Git 상태, 빌드, 운영 기록, 원격 저장소
- 새 저장소 확인: 생성할 정확한 경로, 부모 Git 경계, 원격 이름 충돌, 템플릿 이력 분리
- 공통 확인: 라이선스, 사용 가능한 모델·도구·MCP, 다운로드 권한, 비용 제한
- 산출물: 저장소 규칙, 실행 명령, 운영 문서, 첫 작업
- 게이트: 빈 환경에서 설치·실행 가능하며 템플릿 원본의 Git 이력이 섞이지 않음

## 1. 제품 프레이밍

- 확정: 대상 플레이어, 플레이어가 반복할 동사, 세션 길이, 성공·실패, 플랫폼·입력, 범위·비범위
- 산출물: 한 페이지 브리프, 성공 지표, 가장 큰 제품 위험 세 개
- 게이트: 팀원이 같은 핵심 루프를 한 문장으로 설명하고 첫 수직 조각의 종료 상태가 관찰 가능함

## 2. 병렬 사전 제작

- 게임 디자인: 규칙, 경제, 진행, 온보딩 가설
- 기술: 엔진 비교, 아키텍처, 테스트와 배포 스파이크
- 아트·UX·에셋: 기능 팔레트, 화면 계층, 제작/다운로드 결정, 라이선스
- 사운드: 이벤트 목록, 믹스 우선순위, 절차 합성/외부 소스 결정
- 내러티브: 플레이를 설명하는 최소 용어와 맥락
- 게이트: 충돌하는 제안이 ADR 또는 통합 계획에서 해소되고, M1 범위에서 뺄 것이 명시됨

## 3. 위험 우선 수직 조각

- 구현: 시작, 핵심 행동, 목표, 실패 또는 성공, 재시작
- 구조: 규칙 상태와 렌더·입력·오디오·플랫폼 어댑터 분리
- 검증: 결정론 또는 재현 가능한 상태, 실제 입력, 중간 상태, 결과 화면, 런타임 오류 로그
- 게이트: 한 세션의 시작부터 결과까지 자동 또는 재현 가능한 절차로 완주함

## 4. 콘텐츠와 도전 깊이

- 각 도전 단위는 `소개 → 요구 → 조합 → 시험 → 변주` 중 하나의 역할을 가진다.
- 난이도는 수치만 올리지 않고 공간, 목표 순서, 규칙 수, 정보량, 행동·시간 예산, 자원, 위험 조합, 회복 기회 중 한두 축만 바꾼다.
- 액션·공간 게임은 스폰, 목표, 경로, 충돌과 소프트락을 확인한다. 퍼즐·카드 게임은 해법 존재, 교착, 의도하지 않은 지름길, 행동 예산, 무작위 공정성과 되돌리기를 확인한다.
- 게이트: 모든 도전 단위를 완료할 수 있고 학습 목적, 난이도 증가 이유와 실패 원인을 설명할 수 있음

## 5. 게임 필·FX·사운드·UX

- 행동별로 `예고 → 발생 → 결과` 피드백을 화면, 소리, 상태 텍스트 중 두 채널 이상에 배치한다.
- 타격, 피해, 처치, 이동기, 목표 상호작용, 구역 전환을 우선한다.
- 흔들림, 섬광, 반복 애니메이션, 음량은 접근성 설정에서 줄이거나 끌 수 있어야 한다.
- 게이트: 빠른 장면에서도 플레이어가 성공·피해·목표 변화를 구분하고 오류 없이 진행함

## 6. 사람 플레이테스트

- 관찰자는 조작을 설명하지 않고 첫 목표 이해 시간, 막힌 지점, 사망 원인 인식, 재도전 의향을 기록한다.
- 작은 표본은 방향 신호로 사용하고 통계적 확정처럼 표현하지 않는다.
- 게이트: 사전에 정한 성공 기준을 통과하거나, 실패가 재현 가능한 수정 작업으로 분해됨

수직 조각이 목표 세션으로 확장될 수 있는지도 확인한다. 새 판단 없이 같은 콘텐츠만 반복되거나 짧은 조각의 피로가 세션 길이에 맞지 않으면 `Reframe`한다.

## 7. 공개 빌드와 미디어

- 클린 설치, production build, 대상 플랫폼·기기 스모크, 크레딧과 라이선스를 확인한다.
- 플레이 영상은 실제 빌드와 실제 입력을 기록한다. 메뉴, 핵심 루프, 난도 증가, 결과를 포함한다.
- README에는 게임 방식, 실행, 조작, 현재 범위, 영상과 크레딧만 전면에 둔다.
- 게이트: 새 환경 실행, 링크·미디어 무결성, 영상 프레임 연속성, A/V 싱크, 공개 문체 검토가 통과함

## 8. 회고와 승격

- 사용자 교정, 재작업, 비자명한 해결을 사건·원인·검증으로 기록한다.
- 특정 게임 사실은 프로젝트 메모리, 장기 선택은 ADR, 두 번 이상 성공한 절차는 스킬 후보로 분류한다.
- 게이트: 다음 프로젝트에서 실제로 재사용할 항목과 버릴 항목이 분리됨
