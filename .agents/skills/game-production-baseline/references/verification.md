# 게임 검증 증거

## 증거 사다리

낮은 단계가 높은 단계를 대신하지 않는다.

1. 정적 검사: 타입, 린트, 자산 경로, 라이선스 필드
2. 단위·통합 검사: 규칙, 수치, 상태 전환, 결정론
3. 프로덕션 빌드: 배포 경로, 번들, 새 설치
4. 입력 통합: 모델 action replay, 엔진 입력 event, OS 수준 실제 입력을 주장에 맞게 구분
5. 상태 관찰: 핵심 상태를 구조화된 텍스트나 디버그 HUD로 비교
6. 시각 확인: 기준 해상도와 극단 해상도에서 캡처하고 직접 검토
7. 청각 확인: 이벤트별 소리, 음량, 겹침, 음소거, 전환 시점을 청취·측정
8. 인간 검증: 설명 없는 이해, 재미, 난도, 재도전 의향

## 플레이 변경의 최소 증거

- 입력: 어떤 키·포인터·패드 조작을 했는가
- 중간 상태: 행동이 규칙에 반영됐는가
- 결과 상태: 성공·실패·점수·진행이 맞는가
- 화면: 상태와 화면이 일치하고 겹침·잘림이 없는가
- 오류: 런타임·화면 오류가 새로 생기지 않았는가

화면과 상태 텍스트가 다르면 화면을 사용자에게 보이는 실제 결과로 보고 원인을 수정한다.

## 결정론과 시간

- 가능한 경우 `state + input + fixed tick -> next state` 형태로 규칙을 격리한다.
- 같은 seed와 입력을 반복해 상태 hash 또는 주요 필드를 비교한다.
- 실제 실행 시간과 테스트용 시간 진행을 분리하되, 둘 사이의 행동 차이를 검증한다.
- 일시정지, 재시작, 구역 전환, 프레임 지연과 긴 입력 간격을 포함한다.

## 입력 증거의 수준

- 모델 action replay: 규칙과 기록 재현을 증명한다. 실제 장치나 UI 연결은 증명하지 않는다.
- 엔진 입력 event: 엔진 장면과 입력 매핑 통합을 증명한다. OS 포커스·좌표·장치 동작은 별도다.
- OS 수준 입력: 배포 빌드에서 사용자가 실제로 조작할 수 있음을 증명한다.

프로젝트 스택에 맞는 실행·headless·캡처·로그·export 방법은 해당 버전의 공식 문서로 확인하고 검증 프로필에 기록한다.

## 레벨과 난이도

- 공간 게임에서는 목표, 캐릭터와 위험 요소가 충돌 지형 안에 생성되지 않는지 정적 검사한다.
- 경로 탐색 또는 실제 자동 입력으로 최소 통과 폭과 병목을 확인한다.
- 구역별 완료 시간, 피해, 처치, 실패 지점, 사용한 능력을 기록한다.
- 자동 완주는 가능성을 증명할 뿐 재미나 도전 욕구를 증명하지 않는다.

## 퍼즐·카드·턴제 도전

- 모든 필수 문제에 최소 한 개의 해법이 존재하는지 확인한다.
- 0행동 성공, 규칙을 우회하는 지름길과 성공·실패 동시 판정을 검사한다.
- 해법 길이가 행동·턴 예산 안에 있고, 무작위 분배가 회복 불가능한 교착을 만들지 않는지 확인한다.
- 되돌리기 후 권위 상태가 복구되고 같은 seed와 행동이 같은 결과를 만드는지 확인한다.
- 자동 해법은 해결 가능성을 증명할 뿐 발견의 즐거움이나 힌트 적절성을 증명하지 않는다.

## FX와 사운드

- 타격 이벤트와 muzzle, spark, hit stop/shake, SFX가 같은 게임 사건에 연결되는지 확인한다.
- 다수 이벤트가 같은 프레임에 발생할 때 중요한 소리가 묻히지 않는지 확인한다.
- reduced motion, 음소거와 음량 조절에서도 게임 상태를 알 수 있어야 한다.
- 절차 합성도 외부 자산과 마찬가지로 재현성과 대상 런타임의 오디오 정책을 확인한다.

## 플레이 영상

- 실제 게임 화면과 오디오 출력을 같은 시간축으로 캡처한다.
- 고정 tick 여러 개를 한 렌더 프레임에 몰아 넣지 않는다. 영상은 중간 동작을 건너뛰고 소리는 현재 시간에 몰릴 수 있다.
- 컨테이너 전체 길이만 비교하지 말고 구역 전환, 타격, 완료 이벤트의 프레임과 파형을 대조한다.
- 속도 변경은 영상과 오디오에 동일하게 적용한다.
- README 미디어는 파일 크기, 해시, 링크와 대표 프레임을 검증한다.

## 완료 보고 형식

- 주장: 무엇이 완료됐는가
- 증거: 실행한 명령, 입력 경로, 상태, 캡처, 측정값
- 미검증: 사람 테스트 등 아직 닫히지 않은 항목
- 위험: 다음 변경에서 다시 확인할 조건
- 되돌리기: 안전하게 이전 상태로 돌아가는 방법
